# Репозиторий Lab и путь к предложениям в CoMaps

Проверено 12 ноября 2026. Это AI-assisted технические заметки для владельца
репозитория, а не готовые тексты для отправки в CoMaps.
Точные вершины веток, сравнение истории и хеши прочитанных правил сохранены в
[снимке аудита](evidence/repository-audit-2026-11-12.json).

## Что хранится на GitHub

`pvl-grdv/comaps-icloud-ci` — небольшая лаборатория с патчами, фикстурами,
сценариями CI и результатами. Это не полный fork исходников CoMaps и не зеркало
его истории. CI получает нужную версию настоящего CoMaps из Codeberg и применяет
к ней выбранный патч. Переносить всю эту лабораторию в upstream не требуется.

На GitHub сейчас шесть веток. Главной по настройке репозитория является `main`,
но актуальная работа, отдельные патчи и отчёты находятся в `comaps-lab`.
Поэтому обычная ссылка на репозиторий показывает старый октябрьский эксперимент.

Для самой лаборатории достаточно одной активной ветки `comaps-lab`.
Исторические этапы удобнее обозначать тегами: они сохраняют точный код, но не
выглядят как шесть параллельных незавершённых работ. Предлагаемая уборка:

1. Сохранить точные исторические вершины архивными тегами и проверить их на сервере.
2. Сделать `comaps-lab` главной веткой GitHub, чтобы стартовая страница вела к актуальным материалам.
3. Проверить ссылки в инструкциях и старые фильтры веток в CI.
4. Только после этого удалить ненужные старые ветки по отдельному решению владельца.

Этот аудит не удаляет ветки, не меняет default branch, не переписывает историю
и не обновляет `main`. Старые успешные прогоны относятся к своим точным коммитам;
переименование или удаление ветки не делает их проверками нового кода.

## Как предложить изменения в CoMaps

Для обычного PR нужен fork настоящего `comaps/comaps` на Codeberg с его историей.
В этом fork `main` остаётся чистой базой upstream. От неё создаётся отдельная
ветка на каждую предлагаемую идею. В такую ветку попадают исходники и тесты
из одного самостоятельного патча, а не файлы `.patch` и не история нашей Lab.
GitHub можно оставить для проверок и доказательств; второй полный mirror не обязателен.

| Предложение | Откуда взять изменение | Что уже проверено / что осталось |
| --- | --- | --- |
| Поиск точек и треков | `saved-items/search.patch` | Независимый CI на `871febff`: 19 XCTest, 12 native проверок, Release. Перед подачей актуализировать базу и пройти человеческое ревью. |
| Ручной порядок папок | `saved-items/folder-order.patch` | 9 XCTest, 3 native проверки, Release на той же базе. |
| Ручной порядок точек и треков | `saved-items/item-order.patch` | 13 XCTest, 8 native проверок, Release; проверены снимки управления порядком. |
| Open With и безопасный импорт | `open-with/open-with.patch` | Отдельный кандидат; актуальный результат и ограничения в `open-with/README.md`. |
| Надёжность iCloud и остальные исправления | `candidates/` и интегрированная серия | Требуют самостоятельного выделения/проверки; для iCloud ещё нет подтверждения живой синхронизации нескольких устройств. |

Три патча поиска/порядка применяются независимо к чистой базе, это не готовый
последовательный набор. Когда одно предложение будет принято, остальные нужно
перебазировать, разрешить пересечения и заново проверить. Ветки реальных PR
сохраняются до завершения рассмотрения; их количество определяется работой,
а не нынешними шестью экспериментальными ветками.

## Что нужно перед отправкой

CoMaps просит одну идею с её тестами в каждом PR, рабочие коммиты и проверки
затронутых платформ; для визуальных изменений — примеры до/после.
Текущий CI на Mac/iOS сам по себе не доказывает сборку изменённого общего C++
кода на Android и других платформах.

Правила AI требуют раскрыть помощь AI, лично прочитать и понимать код,
самостоятельно написать предназначенные людям тексты, включая сообщения
коммитов, комментарии кода и описание PR, и получить человеческое ревью.
Проверки агентов внутри Lab не являются таким одобрением. Историю наших
экспериментальных коммитов с AI-generated сообщениями не нужно переносить в PR.
DCO подтверждает сам автор; в этой лаборатории подпись за пользователя не ставится.
Указания на Organic Maps нужны там, где действительно заимствованы код или идеи.
